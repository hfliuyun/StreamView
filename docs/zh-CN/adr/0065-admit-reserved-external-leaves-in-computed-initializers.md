# 在计算字段初始化式中接纳保留的外部叶子

状态：已接受
日期：2026-08-08

## 背景

ADR-0064 完成了有界的参考图像标记。内置档位的下一个增量是
`pred_weight_table()`。按第 7.3.3 条，当 P 或 SP 条带使用的 PPS 置位了
`weighted_pred_flag`，或者 B 条带使用的 PPS 满足
`weighted_bipred_idc == 1` 时，需要读取该表。

本决策的初稿提议立即加入该表，并用一条源锚定断言收窄接受档位，使表项数量始终
等于导入的 PPS 默认值。对编译器的探测否证了该初稿。探测结果记录在此，因为它们
约束了后续每一种尝试。

针对内置规则确认了四项语言限制。

计算字段的初始化式不接纳导入上下文叶子。解析器在校验计算表达式时禁用了外部
引用，因此其中的 `context_value(...)` 会被报告为未声明的纯函数，而不是被解析。

计算字段无法引用在条件分支内部作出的声明。编译器报告该依赖"在当前分支上不被
保证"，正是这条规则最初把初稿推向了收窄方案。

收窄断言本身没有合法位置。放在顶层时，它同样违反分支保证规则，因为
`num_ref_idx_active_override_flag` 声明在 `if (uses_reference_lists)` 内部；
移入该条件分支（标志位在此可用）后，又因"断言必须是无条件的顶层项"而被拒绝。

固定两次迭代的重复无法表达。单参数的 `repeat (integer)` 形式一律是哨兵形式，
必须带 `until` 子句，因此色度分量必须显式命名，而不能投影为两元素循环。

初稿假定存在的两项能力得到确认。带算术运算的 `computed<u64>` 可以作为计数重复
的控制器；在条件分支内部声明的 `computed<bool>` 可以在同一分支中守护后续条件。

结论是：`pred_weight_table()` 需要有效表项数量；该数量要么来自本地覆盖字段，
要么来自导入的 PPS 默认值；语言中没有在二者之间选择的表达式；而能够回避这一
选择的限制条件又无法书写。因此该表不能在本增量落地。但每一种候选设计都确实
需要一项能力：在计算字段初始化式中读取外部值。该表的存在性守护恰好就是规范
针对两个导入 PPS 字段给出的条件，而 `if` 语法只接受计算布尔标识符、字段相等
比较，或 `context_value(...)` 相等比较，因此这个双子句守护别无栖身之处。

## 决策

在计算字段初始化式中接纳两个保留的外部叶子 `context_value(...)` 与
`header_value(...)`。这是为既有机制增加一个位置，不引入新语法、新表达式种类，
也不引入新操作码。

```cpp
computed<bool> uses_explicit_weighting =
    (is_p_slice &&
     context_value(pic_parameter_set_id, h264_pps, weighted_pred_flag) == 1) ||
    (is_b_slice &&
     context_value(pic_parameter_set_id, h264_pps, weighted_bipred_idc) == 1);

computed<u64> effective_l0_count =
    context_value(pic_parameter_set_id,
                  h264_pps,
                  num_ref_idx_l0_default_active_minus1) + 1;

computed<bool> is_reference_picture = header_value(nal_ref_idc) != 0;
```

两个叶子一并接纳，而不是逐个放开。它们是同一机制指向两个不同外部来源，在相同
的三处既有位置一起启用和禁用；只接纳其一而拒绝另一个，对规则作者而言是需要额外
记忆的任意不对称。

每个叶子既有的全部约束保持不变。导入上下文叶子仍要求外围结构声明匹配的
`@context_import`，仍将其键解析为更早的、具备上下文资格的字段，并且仍只能触及
唯一发布结构的导出字段。序列元素叶子仍针对程序中唯一的扫描元素结构解析，仍拒绝
自引用与缺失扫描，并且仍只能触及无条件、顶层、非数组的无符号标量。若结构未声明
导入，其中的计算初始化式会被拒绝，与动态位宽位置既有的拒绝方式完全一致。

叶子仍为 `u64`，并计入相同的表达式节点与深度预算。它们在纯函数体和惰性字节计数
中仍然不被接纳。

运行时无需改动。虚拟机在求值计算表达式时，本就同时传入导入上下文解析器与元素值
向量，因此求值语义正是断言位置与动态位宽位置自 ADR-0063 起一直使用的语义。只有
静态闸门发生位移：解析器的计算表达式校验、类型化 IR 的计算字段下降，以及虚拟机
的计算字段校验，现在各自放开了周边位置早已放开的内容。

由于计算字段可以充当计数重复的控制器，本决策也首次让导入或首部派生的重复计数
成为可表达的。该组合由一个端到端会话用例覆盖：从首部字段读取的计算计数恰好接纳
`nal_ref_idc + 1` 次迭代，并且恰好消耗预测的位数。

回归覆盖包括：解析器在计算初始化式中接纳两个叶子；类型化 IR 下降为既有的
`ImportedContextReference` 与 `SequenceElementReference` 种类且不新增操作码；
编译阶段对缺失导入的拒绝；以及上述运行时组合。

## 结果

计算字段现在可以依赖参数集，或依赖其所属 NAL 单元的首部。这解除了
`pred_weight_table()` 存在性守护的阻塞（其条件读取两个导入 PPS 字段），并使
依赖性表项数量在计数重复所要求的位置上成为可表达的。

内置规则被刻意保持不变。预期的清理已在 H.264 规则的临时副本上验证通过：两条断言
收拢为单一的 `uses_explicit_weighting` 守护，ADR-0064 中反转的空 `then` 分支替换
为 `is_reference_picture` 计算字段，规则编译干净。但现在应用它，会在非 IDR 条带
结构末尾附近新增两个具化的计算节点，从而在 24 个分析器测试、106 处硬编码位置上
移动子节点索引，而换来的解码行为没有任何变化。这类改动应归入同时加入该表的那个
增量——在那里这些节点是必需的，而非仅仅更整洁。

数量选择问题仍然悬置，是接下来要作出的决策。两种可行形态是：在覆盖分支与默认
分支下各复制一份表体并采用不同的字段名后缀，这在今天即可表达，代价是四份近乎
相同的副本，以及随一个无关标志而变化的字段名；或者加入一种依赖分析具备流敏感性
的默认取值表达式，这样能保留规范自身的命名，代价是再作一次能力决策。第二种更
可取，因为复制会在后续每一张表上叠加，但那是一项独立决策，不在此处作出。

在多一个位置接纳叶子，会扩大上下文查找在执行期而非编译期失败的面。该暴露正是
ADR-0063 已经接受的那一项：位于永不作为载荷分发的结构中的 `header_value` 调用
可以编译通过，随后在没有提供值向量时以无效定义失败。

## 非目标

本决策不加入 `pred_weight_table()` 或任何内置规则语法，不改变内置包版本，也不
解决数量选择问题。它不加入条件表达式或默认取值表达式，不使计算字段的依赖分析
具备流敏感性，也不允许计算字段引用条件分支内部的声明。它不在纯函数体或惰性字节
计数中接纳这两个叶子，不放宽任一叶子既有的任何约束，不扩大上下文种类的封闭集合，
不改变上下文世代解析，不加入通用的跨结构字段访问，也不新增或改变任何操作码。
